# F2 → F3 确定性转换程序：详细设计

日期：2026-09-25。版本：设计稿 0.1。**状态：设计已保存，下面新增模块、接口和验收流程尚未实现或运行；不是已有实验结果。**

## 1. 目标与核心决定

将原论文分析器输出的最终 Error Invariant（EI）形式化谓词，转换成可机械检查的受控自然语言（CNL）。转换不解释缺陷成因、不建议修复、不调用任何生成式模型。GPT/Codex可以开发通用工具，但正式流水线中的逐案例内容只由冻结工具产生。

不是“让另一个模型读公式再改写”，也不是把整份分析日志翻译成中文。具体路径是：

`已确认完成的分析日志 → 最终 Map → 方言解析 → 带类型语法树 → 固定中文模板 → 独立反向解析 → 配对导出`

F2保留最终Map中的原始谓词；F3使用同一谓词的模板化中文。两者共享同一源码、失败信息、切片标记、程序点解释、符号定义、分析轮次和任务要求。模型输入中唯一设计上的变化是EI表达形式。

本设计将正式F3限定为**全部谓词成功转换的纯CNL视图**。遇到不支持的表达式，保留诊断记录，但阻止该案例F2/F3正式配对导出。旧协议允许标记混合表达；混合表达在本设计中仅作诊断产物，不能冒充正式F3。此项是新增导出约束，不回写历史输入。

## 2. 已有基础与实际语法

### 2.1 已实现和未实现的界限

已有提取器：`03_experiments/prototypes/error_invariant_pipeline/extract_final_error_invariants.py`。

它能够提取多个Map、检查最后一轮停止标志、保留原始分区元数据与最终切片；当前输出版本为`final-ei-0.1`。其明确状态包括：

- `partition_metadata_status = raw_only_symbol_mapping_not_verified`；
- `source_mapping_status = not_generated`；
- `model_jobs_status = not_generated`。

因此“日志提取成功”不等于“符号已解释”“已生成F2/F3”或“已证明EI正确”。本设计新增适配层，不改变旧提取器及历史产物。旧`parse_error_invariants.py`提取第一轮Map的路径，不用于本转换器。

### 2.2 当前开发语料

检查范围：`03_experiments/outputs/f_protocol_preparation_2026-09-22/extracted_v2/`中的11份案例产物，以及对应历史分析日志。11份均有3轮；最终Map共145个位置谓词，其中9份各13个、Seed07与Seed10各14个。这是开发语料清点，不是转换测试通过数，也不是145个独立缺陷。

实际出现的构件包括：`B1 Bool|`、`not B1 Bool|`、`&&`、`||`、`==`、`>=`、负常数、`-x`、`x+z`、`-x+z`、`bottom`，以及分支内的`top`。元数据还出现`<=`。

Seed01最终位置5的原文为：

```text
B1 Bool| && x >= 10 && -x >= -20 && x+z == 20 || not B1 Bool| && -x >= -9 && z == 10
```

Seed10存在：

```text
B1 Bool| && x == 9 || not B1 Bool| && top
```

早期中间诊断中还出现`9x+10z >= 181`。它不是上述最终Map语料的已确认语法覆盖项；隐式系数应另设方言扩展，不能凭中间日志就声称最终谓词解析已支持。

## 3. 正式转换前必须解决的语义问题

### 3.1 BDD符号不能根据出现顺序猜测

`B1 Bool|`必须作为特定打印方言的布尔原子识别，不能按单个`|`分割。Seed01元数据打印`predicates1 : x >= 10 :`，但这不足以证明B1在所有轮次、位置都等同于“当前x大于或等于10”。需要核对分析器实现中的符号分配、极性、作用域及状态时刻。

实现方式按优先次序选择：

1. 核对对应版本分析器源码，编写按版本适用的元数据适配器；若日志信息充分，从日志生成符号表。
2. 若日志缺失，给分析器增加仅输出元数据的接口，输出BDD变量ID、定义、轮次、绑定状态和程序点。保留旧二进制及旧日志，使用新批次；核对数值分析结果有无变化。
3. 若仍不能恢复映射，状态为`SYMBOL_UNRESOLVED`，不正式导出。允许生成“布尔符号B1为真”的诊断文本，但不能声称它已经解释了程序条件。

人工可以审查通用适配规则，不能为单个案例写一个猜测的B1定义以使案例通过。

### 3.2 程序点不等于源码行

Map的`[5:]`是分析器标签，不自动等于源码第5行。必须区分原程序AST标签、最终切片AST标签、源代码范围。映射记录应包含语句ID、字节范围、函数作用域及状态位置（语句前、语句后、分支入口、循环头或出口）。

优先在分析器前端输出源码范围及程序点类型；其次采用已验证的前端结构映射。禁止按“最近的行”或仅相同语句文本匹配。重复语句、变量遮蔽、一行多语句、空出口点必须显式处理。一个程序点可有多个来源范围，但集合必须准确、双方一致，不把歧义伪装成精确定位。

### 3.3 数值域和抽象语义

必须记录分析器版本、抽象域、变量类型及算术模型。`polyhedra`配置本身不足以确定所有表达式使用数学整数、实数还是机器整数语义。不能因为源代码写`int`，就直接把多面体关系解释为包含溢出的C执行语义。

`top`译为“在当前抽象域中，不附加约束”；`bottom`译为“在当前抽象域中，状态集合为空”。启用这些模板前必须确认工具含义。它们不译成“程序正确”“该行永不执行”或“必然发生错误”。所有视图共享声明：这些是抽象分析的状态关系，不是具体失败轨迹，也不是补丁正确性规格。

## 4. 模块划分与接口

拟建目录：`03_experiments/prototypes/error_invariant_pipeline/f_evidence_translation/`。下表均为计划接口。

| 模块 | 输入 → 输出 | 职责与拒绝条件 |
| --- | --- | --- |
| `ingest.py` | 原日志、提取JSON、manifest → FinalMap | 校验来源哈希和最终轮次，重新定位原文范围；不接受仅凭文件名关联 |
| `dialect.py` | 工具版本 → DialectSpec | 冻结token、优先级、数字域及允许构件；未知版本拒绝 |
| `lexer.py` | 单条原谓词 → Token序列 | 完整消费，保存原文区间；未知字符拒绝 |
| `parser.py` | Token序列 → PredicateAST | 递归下降，保留次序、否定与分组；不得调用eval |
| `bindings.py` | 工具元数据、源码映射 → BindingTable | 校验符号、变量作用域、程序点及状态时刻 |
| `render_cnl.py` | AST、绑定 → CNL文本 | 纯函数、固定模板，不读取参考程序或评价标签 |
| `parse_cnl.py` | 实际导出的CNL文本 → AST | 独立文法反向解析；不读取原AST来“恢复”文本含义 |
| `verify.py` | 原AST、反向AST、绑定 → 检查报告 | 结构、类型、绑定和完整性校验；可接本地语义检查器 |
| `export_pair.py` | 已通过检查的案例 → F2/F3输入 | 白名单投影、共同字段比较、长度检查、只写新批次 |
| `cli.py` | 本地文件参数 → 状态码与产物 | 无模型调用、无SSH、无自动重跑分析器 |

建议函数签名：

```python
parse_predicate(raw: str, dialect: DialectSpec) -> PredicateAST
resolve_bindings(ast: PredicateAST, metadata: ToolMetadata) -> BindingTable
render_cnl(ast: PredicateAST, bindings: BindingTable) -> str
parse_cnl(text: str, symbol_catalog: SymbolCatalog) -> PredicateAST
verify_translation(original: PredicateAST, recovered: PredicateAST,
                   bindings: BindingTable) -> VerificationReport
export_pair(case: VerifiedCase, protocol: FrozenProtocol) -> PairArtifacts
```

`SymbolCatalog`只包含合法符号名和类型，不包含原公式树。反向解析器可以共享类型定义，但不得调用正向解析器或渲染器作为解析捷径。

## 5. 数据结构及可追溯性

### 5.1 案例manifest

必填字段：`schema_version`、内部`case_id`、`source_sha256`、`log_sha256`、`analyzer_build_id`、`analyzer_config`、`numeric_semantics_id`、`dialect_version`、`final_round`、`source_map_sha256`、`bindings_sha256`、`translator_version`、`template_version`、`protocol_version`。

每个来源文件均登记相对路径、内容哈希、产生步骤和状态。历史日志无法证明对应哪份源码时，不补造来源，标记`PROVENANCE_INCOMPLETE`。绝对路径仅供私有审计，不进入模型提示词。

### 5.2 类型化AST

谓词节点：`Top`、`Bottom`、`BoolRef`、`Not`、`And`、`Or`、`Compare`。算术节点：`Number`、`Var`、`Neg`、`Add`、`Sub`；标量乘法作为扩展节点`Scale`，首版不默认启用。

每个节点包含`kind`、有序子节点、类型、原始日志范围。变量节点使用带作用域的内部ID，而非仅字符串`x`。BDD节点使用轮次作用域ID。数字按精确十进制整数字符串保存，不经过浮点数；有理数、科学计数法等未启用时拒绝。

示例结构（省略跨度）：

```json
{
  "kind": "Compare",
  "op": "ge",
  "left": {"kind": "Neg", "arg": {"kind": "Var", "id": "main::x"}},
  "right": {"kind": "Number", "value": "-20"}
}
```

原打印文本独立保留，不用AST重新打印结果覆盖F2原文。日志字节范围和换行标准化后的字符范围分别标注；现有提取JSON合并换行，不能据它反推精确字节跨度。新适配器从原始日志建立跨度并核对合并文本一致。

### 5.3 绑定表

每个符号条目含：内部ID、显示名、类型、作用域、来源位置、定义来源、状态时刻、验证状态。BDD额外含变量编号、极性和定义表达式；程序点额外含命名空间、点类型、源码范围和切片成员映射。

任何`unknown`状态不得通过正式门槛。定义若含公式，F2/F3采用完全相同的共享定义文本，避免一方得到额外解释；正文不同表达仍仅针对同一最终Map。

### 5.4 审计记录

每个位置记录`raw_predicate_sha256`、`ast_sha256`、`cnl_sha256`、`roundtrip_ast_sha256`、各检查状态、错误码和日志范围。每个案例记录位置总数、转换数、失败数及配对资格。哈希只能证明字节或结构一致性，**不能独自证明解析或翻译语义正确**。

## 6. 形式化打印方言的解析

首版拟支持的文法如下，最终优先级必须与分析器打印实现核对后冻结：

```text
predicate := disjunction EOF
disjunction := conjunction ("||" conjunction)*
conjunction := negation ("&&" negation)*
negation := "not" negation | boolean_atom
boolean_atom := BDD_ATOM | "top" | "bottom" | comparison | "(" disjunction ")"
comparison := arithmetic COMP arithmetic
COMP := "==" | ">=" | "<=" | ">" | "<" | "!="
arithmetic := unary (("+" | "-") unary)*
unary := "-" unary | INTEGER | IDENT | "(" arithmetic ")"
BDD_ATOM := "B" DIGITS WS "Bool|"
```

实施注意：

- 布尔括号与算术括号共用`(`，解析器需要有界回溯或显式预测规则，并在失败时报告最远错误位置；不能把`(x+z) == 20`误判为完整布尔组。
- `||`和BDD打印后缀必须由明确词法规则区分，禁止全局删除`Bool|`再解析。
- 文法中列出的比较符是拟支持集合，不表示每个符号都已在现有最终语料中观察到。
- `not`作用范围必须按方言规则确定；不要按中文习惯扩大到整个后续合取。
- 保留`And/Or`有序列表，不排序、不去重、不分配展开成DNF，不将`top`或`bottom`所在分支删除。
- `-20`可按冻结规则规范为负数字面量，`-x`仍是`Neg(Var)`。不得把`-x >= -20`偷偷改写成`x <= 20`。
- 隐式系数、函数、数组、指针、量词、非线性乘除等进入`UNSUPPORTED_SYNTAX`，不能原样混入正式F3。
- 若增加线性系数支持，应先确认打印器的标识符规则，使`9x`与标识符、数字格式无歧义；新方言版本重新验收。

## 7. 受控自然语言与确定性模板

采用中文固定句法、ASCII结构括号和显式作用域，不追求自由润色。数值保留阿拉伯数字，变量名用转义的名称引号包裹；标点、换行和词语均由模板决定。

| AST | 唯一模板示意 |
| --- | --- |
| `Var(x)` | `变量「x」的值` |
| `Number(-20)` | `负数20` |
| `Neg(x)` | `相反数(变量「x」的值)` |
| `Add(x,z)` | `和(变量「x」的值；变量「z」的值)` |
| `Sub(x,z)` | `差(变量「x」的值；变量「z」的值)` |
| `Compare(ge,a,b)` | `关系(a 大于或等于 b)` |
| `BoolRef(B1)` | `布尔符号「B1」为真` |
| `Not(p)` | `并非(p)` |
| `And(p,q)` | `全部成立(p；q)` |
| `Or(p,q)` | `至少一项成立(p；q)` |
| `Top` | `在当前抽象域中，不附加约束` |
| `Bottom` | `在当前抽象域中，状态集合为空` |

`至少一项成立`包含同时成立，不使用“二选一”或“否则”。共享说明明确“差(a；b)”是前项减后项。允许标识符的字符集和转义必须冻结，反向解析按相同名称编码规则解码，不能让变量名注入结构标点。

### 7.1 真实公式的诊断示例

Seed01位置5按上述模板可生成：

```text
至少一项成立(
  全部成立(
    布尔符号「B1」为真；
    关系(变量「x」的值 大于或等于 10)；
    关系(相反数(变量「x」的值) 大于或等于 负数20)；
    关系(和(变量「x」的值；变量「z」的值) 等于 20)
  )；
  全部成立(
    并非(布尔符号「B1」为真)；
    关系(相反数(变量「x」的值) 大于或等于 负数9)；
    关系(变量「z」的值 等于 10)
  )
)
```

这是待实现模板的人工展示，**不是程序已生成并验证的产物**。B1和程序点尚未完成绑定核验，因此这个示例不能直接导出为正式模型输入。不得加上“所以应修改断言”等分析。

Seed10的第二个分支必须保留：

```text
至少一项成立(
  全部成立(布尔符号「B1」为真；关系(变量「x」的值 等于 9))；
  全部成立(并非(布尔符号「B1」为真)；在当前抽象域中，不附加约束)
)
```

不能将此处`top`写成“整个程序无约束”，因为它位于一个合取分支之内。

### 7.2 可读性与实验边界

受控自然语言仍保留结构括号，这是为了可逆和避免作用域歧义。该实验测“原始形式化打印”与“确定性受控中文”的差异，不等同于任意自然语言解释的效果。若之后改成自由段落，应开新版本，并重新解决等价性校验；不能沿用本版有效性结论。

## 8. 校验设计：如何证明没有翻错

### 8.1 五层检查

1. **来源与完整性**：输入源码、日志、配置对应；存在已确认的最终轮次；位置无重复、无遗漏；不得截取中间轮次补齐。
2. **语法和类型**：原谓词完整消费；每个token有合法归属；数值和布尔类型正确；绑定完整。
3. **实际文本往返**：读取最终F3文件的EI文本，而不是渲染函数内存中的AST；独立CNL解析器重建树，与原解析树比较。只允许冻结的空白、显式分组和负数字面量规范，不做代数等价化。
4. **实现可信度测试**：人工核对的工具语义夹具、独立求值器、变异测试共同检查两个解析器没有共享同一错误。有限枚举只用于发现错误，不称为全域等价证明。
5. **可选本地形式检查**：对支持的数值理论，在已验证绑定与域假设下检查两谓词异或是否可满足。不可满足仅证明给定编码与假设下等价；超时/unknown/未运行分别记录，不能当通过。绑定假设不得取自参考补丁或预期输出。

结构一致性是正式导出的必要门槛；它与通用模板规则的语义审查、方言核对共同构成翻译保证。使用求解器不能代替原打印器语义和源码绑定审查。

### 8.2 模板的可审查性

对每种AST节点建立“形式语义—中文模板—反向规则”三列表并人工确认。以子树翻译保持含义为前提，逐节点说明组合如何保持否定、合取、析取和算术含义。这是受限文法的转换论证，不是自然语言理解模型正确性的证明。

分别保留`structural_roundtrip_passed`、`template_review_passed`、`dialect_review_passed`、`binding_verified`和`solver_status`，不要压缩成一个容易误读的“语义已证明”。

## 9. F2/F3配对导出与信息隔离

共同输入块：原始buggy源码、失败规格和统一失败信息、语义切片标记、合法符号定义、程序点定义、分析语义说明、任务要求。F2特有块仅为原始最终谓词；F3特有块仅为对应CNL。位置顺序和公式数量固定相同。

导出采用新建对象的字段白名单，不把完整实验对象删几个字段后直接发给模型。禁止字段包括参考源码、补丁、根因标签、`ground_truth_source_line`、人工注解、评分和工具调试日志。使用不带缺陷答案的匿名展示ID；内部原始案例名和来源路径只留审计。

配对检查同时比较共同字段内容及哈希，并确认F2每个原谓词与F3每个反向树逐项对应。源代码注释和文件名也须按预先冻结的全局输入策略检查，不能仅靠敏感字段关键词扫描保证无泄漏。

不对F3额外添加推导、区间总结或例子；如需共同的通用语法说明，双方同样提供。模型配置、输出上限、重复次数和任务接口由独立实验协议冻结，本转换程序不选择API服务、不读取API密钥，也不调用模型。

自然语言通常更长，应记录真实token数。服务与tokenizer尚未冻结时状态为`TOKEN_BUDGET_PENDING`，只生成离线草稿；冻结后按同一上下文预算检查两侧，任一超限则整对不能进入正式比较，不单独截断F3。

## 10. 失败策略、资源界限与输出

### 10.1 状态机

`discovered → provenance_verified → final_map_extracted → parsed → bound → rendered → roundtrip_verified → pair_eligible → exported`

任何步骤失败都生成机器可读诊断，后续步骤不伪造成功。案例间可继续处理，案例内不可静默丢掉失败位置。正式共同样本在模型调用前确定，不能根据修复成败回头剔除案例。

错误码至少包括：`PROVENANCE_INCOMPLETE`、`INCOMPLETE_LOG`、`UNKNOWN_DIALECT`、`UNSUPPORTED_SYNTAX`、`TYPE_MISMATCH`、`SYMBOL_UNRESOLVED`、`LOCATION_UNRESOLVED`、`NUMERIC_SEMANTICS_UNKNOWN`、`ROUNDTRIP_MISMATCH`、`INPUT_LEAKAGE`、`RESOURCE_LIMIT`、`TOKEN_BUDGET_PENDING`、`TOKEN_BUDGET_EXCEEDED`。

### 10.2 建议首版上限（实现前冻结）

每条公式最多64 KiB、10,000个token、10,000个AST节点、嵌套深度128；每个案例最多10,000个程序点，单份日志最多64 MiB。达到任一上限则拒绝，不截断。上限是工程建议，不是已测得的最优值。求解器若启用，单条5秒上限，超时单列。

禁止执行公式代码、网络访问、读取环境密钥或运行参考程序。文件路径须解析到允许的输入目录，不能跟随未验证路径访问其他数据。结果目录必须不存在；采用暂存目录完成校验后发布完成标志。失败暂存保留，不覆盖历史，不把半成品标为可导出。

### 10.3 产物布局

```text
<new-batch>/
  manifest.json
  summary.json
  coverage.json
  cases/<private-id>/
    provenance.json
    final_map.json
    bindings.json
    ast.json
    cnl.txt
    checks.json
    diagnostics.json
    model_inputs/F2.json
    model_inputs/F3.json
  COMPLETE.json
```

失败案例不生成正式`model_inputs`。审计文件与模型可读目录分离；`COMPLETE.json`表示批处理结束，不意味着所有案例均成功。汇总必须给出发现、提取、支持、绑定、往返、配对通过与失败数量；每个失败保留在覆盖率分母中。

拟定CLI：

```text
python -m f_evidence_translation.cli inspect --manifest <file> --out <new-dir>
python -m f_evidence_translation.cli translate --manifest <file> --protocol <file> --out <new-dir>
python -m f_evidence_translation.cli verify --batch <dir>
```

以上为接口约定，当前不可视为已存在的可执行命令。`inspect`仅诊断；`translate`没有正式门槛则只输出失败/草稿；`verify`必须重新读取实际产物，不沿用旧通过标志。退出码建议：0为所有请求目标通过，1为存在案例不合格，2为配置或文件错误。

## 11. 测试矩阵与验收

| 测试层 | 输入或操作 | 必须满足的结果 |
| --- | --- | --- |
| 原日志夹具 | 11份开发日志、145条最终谓词 | 精确提取最终轮次；逐条覆盖结果可追溯，不预设全部可正式导出 |
| 词法边界 | `Bool|`紧邻`||`、未知字符、换行 | 无错误分割；未知token明确失败 |
| 优先级 | `a || b && c`、`not a && b`、嵌套括号 | 按经确认的工具方言构树 |
| 算术 | `-x >= -20`、`-x+z == -20`、大整数 | 不变号、不交换减法顺序、不发生浮点舍入 |
| 抽象常量 | Seed10分支内top、单独bottom | 保留作用域，文本不越界解释 |
| 绑定 | B1跨轮次重编号、变量遮蔽、空出口点 | 使用正确命名空间；缺定义拒绝 |
| 日志完整性 | 缺Done、最后轮未停止、重复位置 | 不输出正式结果 |
| 文本往返 | 编辑实际CNL中的否定、比较词、数字、子句 | 检查失败，不能因旁边AST未变而通过 |
| 独立求值 | 小范围整数、独立布尔赋值、边界值 | 原树与反向树结果一致；仅报告有限测试覆盖 |
| 性质测试 | 固定种子生成支持文法的随机AST | render→独立parse保持冻结结构；保留失败种子 |
| 输入隔离 | 在私有记录放参考补丁和假标签 | 导出白名单不包含它们；共同字段完全一致 |
| 确定性 | 不同时间重复、输入目录枚举顺序变化 | 正文及内容哈希一致；时间戳留在独立审计元数据 |
| 资源与写入 | 深层树、超长公式、已有结果目录 | 有界失败；无静默截断或覆盖 |

开发语料不能作为唯一验收集。冻结语法和模板后，使用未参与模板调试的新案例和预留合成边界夹具；新案例如果触发修改，则降为开发数据，并另留验收数据。未支持的案例不能被改写成容易通过的公式。

正式上线门槛：工具方言、数值域、BDD映射和程序点映射有版本化依据；全部适用单元测试和变异测试通过；每个候选案例完成逐位置往返；输入共同块一致；未支持项全部报告；正式模型配置与长度检查另行冻结。不要求把全部11个开发案例强行变成合格案例。

## 12. 分阶段实施与工作量边界

1. **来源与方言确认**：定位分析器版本和打印实现，输出`DialectSpec`及语义审查记录。当前最关键的阻塞是BDD、程序点及数值语义，不能用自然语言技巧解决。
2. **纯解析与渲染**：实现AST、完整词法解析、模板和独立反向解析；先用合成数据及已保存日志离线测试，不运行模型。
3. **绑定适配**：实现自动元数据/源码映射，缺信息时报告；若需改变分析器输出，则另开工具批次，不混入历史证据。
4. **配对导出与隔离检查**：生成只读审计产物，核对每个位置、共同字段和泄漏边界。
5. **冻结和独立验收**：保存代码版本、配置、夹具、测试报告和覆盖率，满足门槛后再准备模型任务。新增模型调用不属于本设计文档的执行内容。

完成上述工作后可声称“实现并验证了受限方言到受控自然语言的确定性转换”。只有实际运行F2/F3且完成独立评价后，才能讨论表达形式是否影响LLM表现。转换成功、Defects4J官方buggy/fixed复现成功，都不等于LLM修复成功。
