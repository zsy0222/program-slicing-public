# FC-Codeflaws v2：源映射、路径后缀条件及同义表达

日期：2026-10-08。这是新的、范围受限的开发协议，不覆盖 v1、原 F/EI 或 J 组记录。当前不调用模型；原生开发验收及确认样本准入未完成前，正式运行保持关闭。

## 1. 方法选择及边界

v1 的具体输入 CBMC 轨迹主要被常量化，不能直接作为内部反向条件。本版另建自动适配器：pycparser 2.21 解析原始源码；从具体 repair 输入产生带源位置的事件序列；在原程序内部位置对观察到的终止路径后缀做反向替换；Z3 5.1.0 检查其与独立前向 SSA 构造的等价性。

这不是原论文 Error Invariant、全路径最弱前置条件或补丁正确性证明。它研究的是**测试派生、带路径上下文的内部状态证据**。Frama-C/CBMC 的旧安装和记录保留，本版不声称已完成其通用 C 后端适配。

支持范围：单个 main、无全局变量、结构化分支/循环、标量 signed int32、无副作用的整数算术表达式、明确分开的自增/自减、具体十进制整数 scanf、单个整数 printf 输出点。相邻 `%d%d` 与空白分隔转换均检查；原程序仍通过 include 原样编译。数组、指针计算、额外函数、浮点、字符串、短路表达式、未知预处理、变量遮蔽等明确拒绝，不删改原程序来适配。

整数条件使用数学整数及显式 int32 定义域；除法向零截断，余数遵循 C 语义。溢出、零除、INT_MIN/-1、未初始化读取、输入耗尽和资源超限不算成功。有界具体执行最多 1,024 次单循环迭代、16,384 个事件；内部位置只从输出前最多 12 个事件内按固定顺序选取相关赋值。Z3 每项义务 5,000 ms，UNKNOWN/超时拒绝。

## 2. 反向条件与源码绑定

共同后置观测为 repair 期望整数输出、单次输出和正常退出。对固定后缀自动计算：

- 赋值 `v=e`：`defined(e) ∧ Q[v←e]`。
- 路径判断 `g`：`defined(g) ∧ observed_branch(g) ∧ Q`。
- 输入：仅替换为该 repair 输入中实际消费的整数。
- 输出与退出：加入共同的输出等式与退出码条件。

`x--` 的判断值从更新后的符号状态重建为 `x+1`，不替换成保存轨迹中的常数。C99 main 隐式返回 0 映射到真实词法闭合大括号，忽略注释中的括号；注释替换保留行列宽度，未知预处理拒绝。

开发 v5 冻结策略为 `FC-scalar-C-path-WP-v2.1-output-data`：候选赋值目标必须出现在独立反向代入得到的**纯输出值表达式**中；仅因路径判断或算术定义域相关的循环计数器不能入选。最终完整条件仍保留路径判断和定义域。条件必须含切点变量、在保存的 buggy 切点状态上为假，并在 int32 替代切点状态域内可满足（SAT）；UNKNOWN/UNSAT 均不录取。这不保证替代状态从程序入口可达。只有输出点等式、恒定轨迹或不可满足谓词不能通过。v4 旧选点记录保留，v5 固定重验同样五例，不补选。

产物保存原源码 SHA-256、切点事件/行/列、变量声明类型与位置、后缀路径、各源行内容和哈希、具体状态（私有审计）、形式 AST、等价义务和工具版本。条件仅约束旧程序的该后缀；不能取反后当作任何新补丁必须满足的规格。

FC1 的静态成员由本版**标量、流不敏感 def-use/control 闭包**生成：保留相关标量全部定义、控制依赖、循环内部退出条件，以及 stdin 消费顺序。它是该受限语法的保守过近似，不是按源码邻近关系取行，也不是 Frama-C 切片、动态切片或通用 C/指针切片。原始完整源码在四组保持一致。

## 3. 形式 AST 与受控中文

只支持封闭、有类型的算术、比较和布尔语法。采用确定性模板，例如“（32位有符号变量「x」加上整数「2」）”；保留显式括号、类型、运算次序、定义域和路径条件。独立递归解析器将中文反解为 AST，要求结构完全相同。不是 JSON 伪装的自然语言，也不调用 GPT/DeepSeek 翻译。

额外检查：反向替换条件与独立前向 SSA 条件在 int32 切点状态域内异或必须 UNSAT。该义务验证两种工具构造的一致性，不证明前端覆盖一般 C 语义；编译器及真实程序有限差分验收另外执行。

FC0：共同完整源码和 repair 失败信息。FC1：再加静态成员。FC2：FC1 加内部形式 AST。FC3：FC1 加同一内部条件的受控中文。四组共同 oracle、源码、编辑范围完全一致；FC3 不夹带另一份形式谓词。理解与修复分为独立无历史任务，不将理解回答传给修复任务。

## 4. 独立性、确认集与防泄漏

仅使用官方快照元数据登记的 3,903 个案例。先按 Codeforces 题目聚类，再按标识符归一化的 5-token 集 Jaccard≥0.90 合并近重复；字面值和运算符保留。当前得到 1,284 个簇。该规则是源码相似性启发式，不声称去除了所有语义重复。

历史已暴露题目全部进入开发域。按固定哈希顺序预留开发簇和 50 个确认候选簇，之后才查看开发结果。开发池不足时按固定增量从剩余保留池扩展，不进入原来的 50 个确认簇；每次扩展开新清单并保存前版哈希。**50 是候选分母，不是已复现/可分析样本数**。最初冻结时确认候选尚未进行基线或分析；本轮后续逐一支持范围检查后录取 0，详见第8节。不得以成功案例替换失败候选。

至少五个不同题目/相似性簇的真实开发程序须通过原生双侧 repair/held-out 基线、包装差分、buggy 解释器观测差分、内部谓词、源映射、中文及义务检查。自建微型程序不能代替这五个。开发源码和已见结果永不作为新确认数据。

reference 源码、accepted 提交号、held-out 输入/输出、参考 diff 均限私有评估。分析接口仅接收 buggy 源码与 repair 输入/期望。正式视图使用 `FCV2-NNN`；删除源注释中的检索身份时保留行列宽度，所有组用同一个公开副本；存在其他身份泄漏时拒绝导出。旧目录 ID、文件路径和 reference 哈希不进入视图。

## 5. 原生与资源闸门

Windows MinGW 的结果仅为 portable 开发诊断，不替代官方 Linux Makefile/比较器。原生验收固定 GNU sed/diff、C locale 与保存的 Makefile 参数，在新目录重验五个冻结代表，不补选。

6 GiB Ubuntu 对本轮单任务验收是合理资源配置；不与 J 的大型 WALA 分析并行。求解任务建议独立 1 GiB 地址空间限额，客机至少 2 GiB 可用、磁盘至少 15 GiB；超限保留记录并停止。该建议不是所有 Codeflaws 程序均能完成的保证。

配置调整遵循安全恢复、正常关机后再改配；不足以恢复时先释放主机内存，不强制丢弃内存状态。2026-10-08 后续执行已在用户正常关机后将 VM 从 12 GiB 改为 6 GiB，固定五例原生验收通过，配置与原状态记录均保留。该执行增量不改变上述分析方法或样本选择规则。

## 8. 确认任务冻结与准入执行增量

理解任务只机械评价**新输入下原始 buggy 程序的整数输出预测**，不把 repair 期望值当预测真值。固定将选中 repair 输入的首整数变为 +1、-1、0，按该顺序构造；重复、原输入、越界、未定义或原生/解释器不一致的探针记录排除，不另找替代。至少一个原生核对探针才可录取；四组问题完全相同、答案仅私有保存。逐例精确准确率再按独立簇平均；格式错误/缺失计0并另报。故障假设、疑似行和保留行为只保存，不使用GPT评分；内部状态同义性未被原生证明，因此不纳入该主指标。这一操作定义测量有限行为理解，不等于完整故障因果理解。

修复任务与理解任务无对话历史共享，返回原行号编辑JSON，四组拥有相同整个文件编辑权限。候选只允许同一受限标量C及原stdio调用格式/顺序；宏、行拼接、未知头文件等拒绝。新目录按冻结Makefile参数编译，完整执行repair及held-out全部测试并用GNU sed/diff比较。每次执行5秒、256 MiB地址空间、1 MiB输出限额；编译每步30秒，整次准入1 GiB地址空间，客机至少2 GiB可用及15 GiB磁盘。候选的超时、格式/范围错误、编译失败、漏测和基础设施失败均不算通过；全测试通过不等于全输入语义正确。参考源码和held-out oracle只进入评估器，不进入模型输入。
