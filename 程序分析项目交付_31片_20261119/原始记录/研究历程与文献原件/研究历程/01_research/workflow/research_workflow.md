# 科研工作流：从问题到可核对的结论

版本：2026-09-12。适用：本项目的文献、实验设计、工具实施、结果审查和论文材料更新。它是协作流程，不表示下列研究功能均已实现。

## 1. 确定本次要回答的问题

以用户当前选择和 `../current_framework.md` 为准。小改动只查相关部分；设计实验时先明确比较对象、主要指标和完成条件。研究审查读已有记录即可，不自动启动新的模型调用。

新实验用 J/F 编号。历史 G1–G6、V2、A–D、D1/D2 保留原编号和批次日期；不得改名后与新协议混算。

## 2. 文献证据与自身结果分别维护

文献矩阵、证据地图和阅读笔记共用 citation key。论文方法、原论文报告的结果、工具 README 与本项目实验各自标注来源。引文记录版本、页节或官方来源；缺少 DOI 的真实文献可以用可核对的其他标识，不编造信息。

文献只支持研究动机和已有方法定义。本项目是否有效，由自己的实验记录回答。更新相关工作时，重点查“真实切片作为修复上下文”“形式化状态证据进入修复模型”“代码理解表现的可执行评价”，避免把 LLM 生成切片和 LLM 读取工具切片当作同一研究任务。

## 3. 冻结一次比较的最小协议

开始批量生成前，记录足以重建该批次的清单：

| 类别 | 必需内容 |
| --- | --- |
| 问题与数据 | 研究问题、纳入条件、开发/留出划分、缺陷版本、触发测试选择规则 |
| 实验条件 | 每组实际输入、允许编辑范围、反馈可见内容、每缺陷重复次数和总调用上限 |
| 实现 | 代码版本或相关文件哈希、工具版本、源码与证据哈希、提示词版本 |
| 模型 | 服务商、请求模型名、返回模型名、实际参数、时间窗口；同批不静默升级 |
| 评估 | 编译、触发、模块回归的命令与判定；理解任务评分规则；超时及失败分类 |

新协议产生新批次目录。对已经见过结果的修改如实标为探索；留出集评价前不根据其成功与否调整规则。已有授权继续有效，只对服务、数据或预算的实质性范围变化补充确认。

## 4. 自动构造并核对模型输入

失败复现 → 定位准则 → 分组源码视图 → 工具证据 → 固定提示词。

检查实际序列化后的输入，而不仅是组别名称。J-C 不得通过编辑块附带完整方法；J-B/J-D 保持同一局部源码；原始错误消息与测试信息按同一投影提供。统一编辑协议，不能让某组靠重建未见源码承担额外格式负担。

C 分析结果须区分轮次、前向/后向状态和最终 Map；只有完成状态确认后才能称为最终结果。自然语言转换保持同一谓词含义，不补写根因或改法。自动化证据生成过程中不引入逐案例 GPT/人工解释；不支持的情况记录为不支持。

保留切片完整产物与送入模型的投影，记录截断、无法映射的行和失败覆盖。参考修复只用于独立评价，不放入模型输入。

## 5. 分阶段运行与验证

先用开发案例检验被修改环节，相关检查通过后再运行该协议内的批次。不要因日常文档修改重复运行整个 Defects4J。

补丁验证：解析/范围检查 → 编译 → 触发测试 → 预先指定模块的全量回归。每项记录真实执行结果；未执行为 `not_run`，环境故障为 `infra_error`，与模型补丁失败分开。不得因文件下载完成就宣布验证成功。

准备独立候选目录时，要同时确保干净的源码和构建产物。基线提交、已安装的官方测试、构建清理方式及测试报告须可追溯。模块回归成功检查实际执行测试数量、失败/错误数和跳过数；仅命令退出码为 0 不足以证明期望测试全部执行。

一次反馈的实验记录首轮、反馈轮及相同初始尝试的对应关系。要声称反馈有独立作用，另设相同调用预算的无诊断重试对照。最终独立评价内容不进入反馈。

## 6. 从原始记录计算结果

唯一键包含批次、策略、案例、重复和阶段。重复记录保留但不重复计数；冲突结果先标记，不按结果优劣挑选。计划的尝试数与实际完成数分别统计。

可使用 `03_experiments/prototypes/research_audit/audit_evidence.py` 复核已登记的历史批次。它只核对保存的结果及文件哈希，不替代重新执行、不证明测试环境正确，也不穷举未登记实验。

按独立缺陷做配对比较，重复生成是缺陷内重复。覆盖率、失败原因、输入长度、分析开销和模型成本一并报告。支持工具的公共子集效果，与所有纳入案例的端到端效果分别呈现。

## 7. 将结果映射到论文主张

更新 `../claim_evidence_ledger.md`，每项主张对应批次、实际对照和边界。先写观测，再写解释；机制猜测明确标为假设。

触发通过表明该失败用例未再失败；模块回归通过表明该测试集未发现问题。二者均不能单独证明所有输入正确或唯一根因。理解指标与修复指标分别报告，不用修复率替代所有“理解能力”主张。

报告保留负结果和失败覆盖。Word/PDF 等展示版本按用户任务生成，日期和协议版本清晰；历史报告不覆盖，当前入口指向最新证据。

## 8. 本轮完成条件

设计任务交付可执行对照与未实现项；实施任务交付修改及相关验证；实验任务交付实际运行状态和结果；审查任务交付证据支持的发现与优先级。环境或授权问题只阻止受影响部分，其他已在范围内的工作继续完成。

这一组织方式参考 OpenAI 官方技能和评估指导，具体分组、统计单位及研究边界是本项目的方法选择，详见 [指南更新说明](../reviews/openai_guidance_update_2026-09-12.md)。
