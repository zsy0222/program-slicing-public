# FC v4：可读输入与完整文件提交的开发协议

日期：2026-10-08。用途：修正 v3 小规模实验暴露的任务接口问题。**本版是开发验证，不是新确认性模型实验；模型执行关闭。** 原 v3 协议、回答、补丁、评价和成绩保留，不用新版重新计分。

## 1. 本次变更与不变项

| 部分 | v4 实现 | 保持不变的边界 |
| --- | --- | --- |
| 输入/输出 | 将既有公开的 hex 记录严格解码为 UTF-8 整数文本，展示有明确起止标记的 stdin/stdout | 不新增题目规格、参考源码、私有答案或 held-out 测试；不能解码时拒绝，不猜测、不替换字节 |
| 源码 | 按物理行显示完整源码，包括空行；行号明确不是代码 | 四组同一源码、旧失败样例和编辑范围，不裁剪或截断任何组 |
| 理解任务 | 强调每道新输入独立运行原错误程序，预测全部整数，不沿用旧失败输出、不预测修复后输出 | 与修复任务隔离；评分仍为完整整数序列精确匹配。解释、故障行和保留行为只存档，不由 GPT 打分 |
| 修复提交 | 严格 JSON `{"source":"完整替换后C程序"}`，整体替换文件 | 不再使用行编辑；不从旧 edits 猜测意图、不提取代码围栏、不修补 JSON/C、不追加旧源码 |
| stdio 闸门 | 仅允许每处 printf 格式末尾一个 LF 的有无变化 | scanf 格式、静态 IO 调用数量和顺序、其他格式字符/转换不变；完整测试仍以原 GNU 比较器判断 |
| Windows 换行 | 只将解析器工作视图中的 CRLF 视作 LF | 保存及交给 GCC 的候选字节不变；不改变字符串中的换行转义，不接受额外行拼接 |
| 失败分类 | 分离提交无效、范围拒绝、编译失败、原生测试失败、未改动和基础设施故障 | 没运行的测试不是通过；编译、repair 和 held-out 各有独立状态 |

上述接口变化同时发生，只能构成一个新的共同任务协议，不能从本轮推断某项单独变更改善了模型表现。原语法后端、源映射、反向条件及 AST↔受控中文生成器没有修改。

## 2. 四组的实际输入

| 条件 | 模型可见证据 |
| --- | --- |
| FC0 | 完整错误源码、同一旧失败输入、实际与期望输出 |
| FC1 | FC0 + 既有工具生成的静态依赖成员行标记 |
| FC2 | FC1 + 旧失败路径固定后缀的形式条件 AST |
| FC3 | FC1 + 同一条件确定性转换出的受控中文，不同时提供 AST |

这不是 J 组静态/动态/双向切片对照，也不是原论文 Error Invariant。路径后缀条件不代表所有输入的规格，不要求补丁机械取反或照搬。理解任务附带同一组新输入；修复任务不接收这些题的答案或理解回答。每例四组×两项独立任务×三次重复，仅用于离线请求预览；重复不能增加独立样本量。

## 3. 提交、测试和统计口径

候选只接受唯一 `source` 字段的 JSON 对象；拒绝重复键、非有限 JSON 数值、空程序、额外 edits 字段、Markdown 围栏和展示行号。解析后原样保存源码，不自动修复或根据测试反馈重试。

仍限制为 v3 支持的单 `int main`、int32 标量/全局变量、长度 1–256 的一维整数数组及已支持的结构化分支循环和纯表达式；宏、额外函数、非允许头文件、外部访问和行拼接等仍拒绝。仅修改 printf 末尾 LF 不能绕过官方比较器；整数相同不等于完整修复通过。

每个合规候选使用既有 Makefile 的编译/链接参数，在独立目录运行全部原 repair 与 held-out 测试，不在第一个失败处提前结束。保留 stdout、stderr、GNU sed/diff、逐测试记录和聚合结果。资源限制沿用原实现：15 GiB 磁盘、2 GiB 可用内存安全线以及候选时间、内存、输出上限，不调整虚拟机资源或删除旧数据。

| 状态/标记 | 含义 |
| --- | --- |
| `invalid_submission` | 未按完整文件 JSON 提交；未编译、未测试 |
| `scope_rejected` | 提交可解码，但不满足语法/安全/IO 范围；源码保留，未编译测试 |
| `compile_error` | 通过范围检查后编译/链接失败；未做候选测试 |
| `test_failed` | 完成全部指定测试，但至少一项不通过 |
| `source_unchanged` | 候选文本与原错误源码相同 |
| `no_effective_change` | 词法 token 序列相同，仅可检测空白/注释层面的未改动；不是一般程序语义等价证明。仍执行全部测试 |
| `infrastructure_failure` | 编译工具缺失、比较器故障、输入变化或资源保护等；单列，不能当模型逻辑错误或通过 |
| `all_tests_passed` | 两套非空测试全部完成且通过；不是所有输入正确性证明 |

正式结果须同时报告计划尝试、有效提交、范围拒绝、编译结果、实际测试数、repair 全过、held-out 全过、两套全过及成功的独立缺陷数。不能只在进入测试的候选中计算一个无条件“修复率”。

## 4. 开发样本、预算和执行闸门

仅复用已经看过 v3 结果的 FCV3-018/019/025/035/038 五簇作为接口开发对照。原 120 次调用不重做、不换分母、不转换旧补丁后重判，也不把五簇重新命名为未暴露确认集。本轮生成 120 份**未发送**的新版请求预览，任务 ID 增加协议命名空间，避免与 v3 调用记录冲突。

新增模型调用为 0；Codeflaws 已记录 120/2,000 次，累计授权不扩大。本版没有网络执行器和新的预算占位操作。继承的模型配置只供预览，不代表当前 API 后端已重新核验。

后续真实模型开发试跑必须另开批次，使用新请求身份、原始回答记录和累计预算保护。先检验真实模型能否遵循完整文件提交接口，再冻结未用于本轮调试的独立确认样本和统计方案。不要把接口验收或参考程序测试通过写作 LLM 修复成绩。
