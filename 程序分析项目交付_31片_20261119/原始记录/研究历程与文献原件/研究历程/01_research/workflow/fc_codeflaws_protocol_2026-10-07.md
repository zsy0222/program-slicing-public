## 1. 研究定义

研究问题：在共同源码、共同失败信息、共同可编辑范围和预算下，程序依赖证据及测试派生状态约束，是否改善模型对故障的理解和测试充分修复？形式 AST 与同义受控中文的差异另行配对。

必须区分三类产物：

1. **测试输出规格**：给定 repair 输入 x，要求运行正常退出，输出满足冻结比较器与期望输出 y 的关系。本轮已实现，属于 oracle 绑定；不包含内部状态推理。
2. **测试派生内部状态约束**：分析器在特定输入、源位置及有界/抽象语义下导出的状态条件。尚未实现和验收；不是原论文 EI。
3. **原论文 Error Invariant**：继续保留旧 F 定义及记录，不与 FC 合并；本轮没有运行该分析器。

不能把“程序能编译”“Clang 能解析”“规格在保存的两次运行上成立/不成立”称为形式化分析完成。也不能把 accepted 源码、参考 diff 或 held-out 输出生成的答案送入模型。

## 3. 基线和输出规格接口（已实现）

`03_experiments/prototypes/tool_adapters/codeflaws.py` 读取原始 C 和实际 `input-posN` / `input-negN` / `heldout-input-posN` 等测试。buggy 在 repair 中至少一个确定失败，reference 在 repair 和 held-out 全部通过，且无缺失/超时/基础设施错误，才标记 `portable_pair_reproduced`。原程序不改写。

本轮 Windows MinGW GCC 12.1、`-std=gnu99 -O0`、`codeflaws_script_portable` 只用于开发诊断。比较器保存行边界、内部空白，分别应用实际输出与期望输出的规范化；不是完全等价的官方 Linux sed/diff 协议。正式运行前必须固定原生编译/链接参数、locale、换行和比较器，双侧重验；新环境开新批，不覆盖本轮。

`fc_oracle_spec.py` 对已准入案例：

1. 只在 repair 失败中按测试 ID 排序确定选择一个；不读 held-out 输出来选规格。
2. 核对 buggy、repair 输入和期望输出的原始哈希；对应 reference 的保存观测必须通过。
3. 构造封闭 AST：`exit_code == 0 AND normalize(stdout) == normalized_expected_line_sequence`。空序列与一条空行不混同，内部空格不变为 token 袋。
4. 在已保存 buggy/reference 观测上核对 false/true；这只是绑定检查，不是程序正确性证明。
5. 用固定模板生成受控中文，独立解析回同一 AST；未知语法、不同 AST 或比较器不符直接拒绝。
6. 公开规格只含 buggy 身份、repair 公共失败信息和规格；reference 哈希/检查结果另存私有评估文件。没有模型任务导出接口。

源绑定目前仅到 buggy 哈希、入口 `main`、观察点 `process_exit`；没有内部变量/故障源码行映射，所以 `formal_model_ready=false`。不能将此规格直接冒充下表的 FC2 分析器结果。

## 5. 形式后端的实施闸门

候选路线是支持完整 C 内存/数组的分析后端，加独立测试 oracle harness。具体版本和方法在开发验收前不算冻结；本轮没有安装可用 C 切片/约束后端。Frama-C/Eva 探针只是前向抽象值能力检查，当前返回 `backend_unavailable`，且并不生成原 EI 或自动解决 stdin/stdout 规格绑定。

后续最低要求：

- 不删除数组、指针、stdio 或副作用来“兼容”；完整 C 前端与实际 ABI/整数类型一致，未定义行为和不支持特性单列。
- harness 只能来自 repair 输入和共同可见 oracle，不来自 reference 源码或 held-out；记录 stdin 消费、输出观察和完整 source-map。
- 原程序与 harness 在 buggy/reference 双侧 repair/held-out 上检查退出码、输出和超时对应；差分一致仍不等于一般语义等价证明。
- 若有界分析，记录所有循环/递归/内存界限、unwinding 状态和剩余未证明性质；SAT/UNSAT/UNKNOWN、资源失败不能混算。
- 静态 C 切片工具先通过分支、循环、数组、别名、跨函数及输出观察点的已知依赖用例；不能使用仅 AST 语法邻近关系却标成语义切片。
- 内部约束须带工具来源、观察点、变量类型、源位置、轨迹/分析上下文、前提与精度边界；未知绑定不进入确认输入。
- 至少 5 个独立开发程序验证后再划分、冻结确认集；当前 3 对输出规格绑定不满足这一分析器验收。
