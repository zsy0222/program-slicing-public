# FC 小规模实验接口修正与验收（v4 开发版）

日期：2026-10-08。任务：针对用户指出的高错误率，修正实验接口，不改写旧实验结果。**修改已实现；本轮没有模型调用，也没有新的 LLM 成绩。** 新版与原 v3 分开，五例已暴露案例仅用于开发。

## 1. 为什么修改

[原五簇小规模实验](fc_small_model_experiment_2026-10-08.md)的四组理解预测均为 20%，全测试修复均为 0/15。60 个候选中 32 个被范围闸门拒绝、28 个进入测试后失败。不能把这 60 个失败全部解释为模型无法理解程序或形式证据无效。

审查发现，原模型输入以 hex 表示失败输入/输出，源码作为 JSON 字符串展示，却要求模型按原始物理行返回 edits。完整程序写进单行 replacement 会与旧文件余下部分拼接；多处行编辑也可能错位。原 IO 闸门还会把仅增加 printf 末尾换行的候选直接拒绝。部分理解回答重复旧失败输出，部分修复候选未产生词法上的有效修改。这些是需要分离的接口/约束遵循混杂，不是全部失败的已证实共同原因。

原 v3 既定评价仍保留：本次没有将旧补丁移到新版重新判分，没有人工修好旧补丁，也没有宣称放宽闸门后的成功率。

## 2. 实际修正

1. 失败输入、实际输出、期望输出和新预测输入严格解码为明文整数流；源码逐物理行编号，包括空行。四组共享部分保持一致，不泄漏参考源码、私有预测答案或 held-out 测试。
2. 修复改为唯一 `source` 字段提交完整文件，直接整体替换。旧 edits、额外字段、重复 JSON 键、围栏及展示行号被明确拒绝，不进行自动意图修复。
3. 仅允许 printf 格式末尾一个 LF 的有无变化；scanf、其他格式、静态 IO 数量和顺序不放宽。最终仍运行全部原 repair/held-out 测试，使用原 GNU 比较规则。
4. CRLF 只在解析器工作视图中规范化；提交、归档和编译的源码字节保持原样，避免 Windows 换行被 pycparser 误拒绝。
5. 理解提示明确要求每题独立预测原错误程序的全部整数，不沿用旧输出、不预测正确程序；整数序列评分不变，GPT 不分析、打分或改写模型补丁。
6. 提交无效、范围拒绝、编译失败、原生测试失败、未改动和基础设施故障分开记录；未改动候选仍做完整测试。词法 token 相同只检测空白/注释式未改动，不是一般语义等价证明。

详细边界见[新版开发协议](../workflow/fc_codeflaws_task_protocol_v4_2026-10-08.md)。这些是共同接口的开发修正，不构成逐例证据补写，也不能识别某项单独改动的模型收益。

## 5. 尚不能得出的结论与下一步

本次证明新版接口在离线和原生正负对照中可用，**没有证明真实模型错误率降低，也没有得到新的四组收益比较**。原 v3 的 20%/0 修复观察不因本次修改消失，但其解释需考虑接口和约束遵循混杂；仍不能据此断言形式证据普遍无效。

当前真实模型接口验收未运行，新确认样本为 0，正式模型就绪标记仍为 false。后续先另开真实模型开发批次检验完整文件提交，再冻结新的未用于调试的确认样本；不能重复使用这五例后称为新确认性证据。更大范围 C 程序支持、完整题意缺失及路径条件适用范围等问题仍在，不因接口修复自动解决。

本轮新增 API 0；既有 Codeflaws 调用仍为 120/2,000，未扩大预算。J 组和原 F/EI 组未在本轮运行。
