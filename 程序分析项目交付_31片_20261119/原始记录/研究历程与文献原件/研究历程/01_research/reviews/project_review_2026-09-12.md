## 总体评价

项目已经具备有价值的探索性原型和可追查的结果记录，超过了仅有概念方案的阶段。最有价值的积累是：接通了程序分析、模型输出和实际测试；保存了原始结果；发现了约束遗漏、编辑范围和触发测试过拟合等具体失败模式。

目前最薄弱的是因果归因和正式评估，而不是实验调用次数。尚不能把现有成果写成“Error Invariant 显著提高 LLM 理解与修复能力”。较合适的定位是：正在研究程序分析证据的输入方式、适用条件与失败机制，并已建立小规模实验管线。

## 优先发现

### P1：当前材料把计划、工具能力与实验事实混在一起

旧 README/current_framework 将“静态前向扩展与剪枝”写成当前流程；paper/AGENTS 仍规定早期 Phase 4，并包含“零运行开销”“LLM 错误只影响精度不影响召回率”等未经当前实验支持的保证。它们会影响后续代理工作和论文表述。

本次已更新这些当前入口，并将早期研究问题标为历史记录。历史实验报告继续保留原内容，通过新的证据台账解释其有效范围。

### P1：组名与实际模型输入不一致

`build_no_llm_repair_jobs.py` 的共同 `candidate` 中包含完整方法；旧 C 还明确附加 `static_context`。因此旧 C 不是纯动态组；旧 A 也得到额外定位和编辑区域提示。`compile_no_llm_evidence.py` 又将切片限制在主类、所选方法内。

新 J-C 需要检查所有序列化字段，而不是只删除一个 `static_context` 键。J-B/J-D 应保持相同源码和编辑方式；纯动态组的格式不能要求复原未见的方法全文。当前只更新协议，没有偷偷改变旧提示词后复用旧结果。

### P1：Error Invariant 的名称遮蔽了不同证据来源

历史 D2 是人工/GPT 辅助的条件化行为规则；自动 Java D 是模式规则；原论文 C 分析器输出才是本研究要测试的形式化 Error Invariant。自动 Gson-12 规则只强调一个数组访问的下界，未形成对整个方法所有相关访问的行为约束；这可解释一种遗漏风险，但不能仅凭补丁形态证明模型因该提示而产生注意偏差。

应将三者分名，保留自动规则的负结果。原论文 EI 的贡献通过 F1/F2 的同案例对照研究，不能由 D2 的 9/9 代替。

### P1：确认性实验尚未形成

当前关键对照集中于少量 Gson 缺陷，多次针对这些案例调整范围、约束和反馈。重复三次主要反映这些任务的输出稳定性，不会把两三个缺陷变成大样本。C 的 11 个变体也属于相近程序族。

建议把现有案例明确作为开发集。先用一个小规模、多项目的留出队列检验管线，再根据覆盖和效应估算正式样本量。可以以 20 个可复现缺陷、至少 3 个项目作为工程扩展起点，但这不是统计充分性的保证。按异常/行为差异、方法长度、跨方法依赖分层，不按哪种方法成功筛选案例。

### P1：干净回归与测试覆盖需要更强的机器证据

现有候选验证脚本创建独立目录，这是优点。但共用 `prepare_worktree` 使用整树复制，测试命令没有统一强制清理构建产物；完整回归判定主要依赖进程退出码，缺少对必需测试数量和测试集合的程序化核验。由此不能仅凭“新目录”证明每次都是干净构建。

此发现不等于已确认历史数值错误。下一轮应保存基线提交、源码差异、工具链、构建清理、测试 XML/集合指纹和退出码，再做独立复现。回归缺失、零测试、超时、环境错误分别记录。

### P2：原始最终产物存在，当前解析和路径管理未跟上

11 份 C 日志均有 3 个 Map、BDD 记录和完成标志；`parse_error_invariants.py` 只取第一个 Map。Seed01 的最终 Map 已包含分区关系，再单独添加同一 BDD 信息可能重复。

本次运行旧 `test_parse_error_invariants.py`：1 项测试因整理前的 `outputs/error_invariants_pilot_2026-08-09/` 路径不存在而失败；相关原始文件实际保存在 `90_local_only/experiment_runs/`。这是已复现的路径问题，尚未修复旧解析器及其测试。下一步应建立小型可提交测试夹具和原始产物定位清单，分别验证“第一轮”与“最终轮”，而不是跳过测试来宣布通过。

### P2：续跑标识和运行记录需要统一

`validate_d2_safe_candidates.py` 的续跑集合只包含案例、重复和阶段，没有策略；工作目录也未包含策略。在多组共享输出或工作根目录时存在串组/误跳过风险。不能据此断言历史分目录运行已被污染，但应在扩展前修正。

新运行标识至少覆盖批次、组别、案例、重复和阶段；记录输入哈希与候选哈希。基础设施重试不计为新的独立模型样本，冲突记录不能凭结果优劣选择。

## 创新性评价与研究取舍

目前可见贡献主要是工具集成、证据表达和实证问题发现。把切片、LLM 与测试反馈串联，本身尚不足以支撑强方法创新主张。本次没有完成最新相关工作的穷尽检索，不能据此断言已有方法是否完全覆盖本设想。

更值得收敛的研究问题是：在相同源码和预算下，故障相关语句标记、形式化状态关系及其自动表达分别增加多少帮助，什么时候反而导致遗漏？让正负结果共同解释适用边界，比只追求“完整工作流最好”的结论更可靠。

优先执行顺序：

1. 完成原始产物路径与最终 Map 解析，固定术语和可复核输入。
2. 冻结 J-B/J-D 主对照及 J-A/J-C 补充对照；F0–F3 在原论文工具支持范围内实施。
3. 固定干净验证、唯一运行键和预算；补齐未完成消融的验证记录。
4. 扩展未用于调试的真实缺陷，并同时测可核对的理解指标与修复指标。
5. 最后研究反馈、更多模型或更复杂约束。反馈收益必须与相同调用预算的重试比较。
