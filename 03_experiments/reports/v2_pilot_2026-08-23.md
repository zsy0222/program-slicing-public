# V2 pilot experiment — 2026-08-23

## Status

This is a workflow smoke test, not an effectiveness claim. It evaluates the two
seeded cases for which Error Invariants completed (`Seed01_update_sign` and
`Seed03_initial_value_v2`). Each initial LLM condition used DeepSeek-V4-Flash,
thinking disabled, temperature 0, and three independent calls. The reference
program and injected-fault fields were excluded from all LLM job payloads.

## V2 additions tested

1. **P-V2a:** source plus Error-Invariant semantic slice, with explicit causal
   roles (`fault_origin`, `error_mechanism`, `control_enabler`, `context`).
2. **P-V2b:** P-V2a plus v0.2 Error-Invariant evidence trajectory, a structural
   analyzer-location-to-source-line map, evidence contract, one targeted
   location-feedback revision, and isolated runtime counterfactual patches.

The location map is necessary because analyzer location IDs and C source lines
are different coordinate systems. It was derived by structural matching of the
analyzer's abstract syntax to the supplied faulty source; it does not use the
reference program or the labelled faulty line.

## Results

| Condition | Responses | Top-1 | Top-3 | True fault labelled `fault_origin` | V2 contract valid |
|---|---:|---:|---:|---:|---:|
| P-V2a role-aware | 6 | 6/6 | 6/6 | 6/6 | 6/6 structural output only |
| P-V2b mapped, initial | 6 | 6/6 | 6/6 | 6/6 | 4/6 |
| P-V2b mapped, after one feedback round | 6 final | 6/6 | 6/6 | 6/6 | 5/6 |

P-V2b made eight actual API calls: six initial calls plus two targeted
revisions. They used 17,411 total tokens with a mean response time of 4.182 s.

### Counterfactual patch validation

Each proposed one-line replacement was applied to an isolated copy, compiled
with MinGW GCC, and executed against the supplied assertion.

| Outcome | Count | Interpretation |
|---|---:|---|
| `validated_by_runtime` | 12 / 14 | Patch compiled and changed the observed program result from assertion failure to normal exit. |
| `rejected_compile` | 1 / 14 | Proposed replacement did not compile. |
| `rejected_failure_retained` | 1 / 14 | Patch compiled but the assertion still failed. |

The true injected edits were ranked first and labelled `fault_origin` in all
six mapped P-V2b responses. However, several alternative control edits also
passed the single assertion. They are **plausible repairs**, not proof of the
developer-intended fault. This is direct evidence for retaining the V2 ambiguity
set rather than reporting every runtime-passing patch as a unique root cause.

### Post-patch Error-Invariant semantic delta

The final Top-1 candidate for each unique seeded case was re-analysed with the
same Ubuntu Error-Invariant analyzer used for the faulty programs. Both analyses
exited normally, reached `the_end : true`, and reported `bottom` at every final
Error-Invariant location (including the original assertion site). In contrast,
the corresponding faulty trajectories retain the error condition `z == 0` at
analyzer location `L12`.

| Case | Top-1 change | Final post-patch Error-Invariant result | Static delta |
|---|---|---|---|
| Seed01_update_sign | `z -= 1` → `z += 1` | all locations `bottom`; `the_end : true` | Original error path eliminated |
| Seed03_initial_value_v2 | `z = 11` → `z = 12` | all locations `bottom`; `the_end : true` | Original error path eliminated |

This adds an independent static check to the runtime result for the two unique
Top-1 candidates. It is not a claim that every alternative runtime-passing
candidate, or programs outside this seeded suite, has been statically verified.

## What the pilot supports

- An explicit static `L-ID -> source_line` map prevents the key failure seen in
  the first V2 attempt, where the LLM confused analyzer locations with C lines
  and produced non-compiling patches.
- Combining source/slice candidate generation with mapped Error-Invariant
  evidence can produce role-aware, location-grounded repair hypotheses on this
  small suite.
- The contract can reject malformed source/evidence bindings, and targeted
  feedback improved the mapped P-V2b acceptance rate from 4/6 to 5/6.
- Counterfactual execution usefully distinguishes compiling, failure-eliminating
  edits from invalid candidates, while exposing multiple viable repairs.
- For both unique Top-1 candidates, the independent Error-Invariant rerun
  eliminates the final static error path as well as the observed runtime
  failure.

## What the pilot does not support

- No claim that V2 improves Top-k localization over G3 source-plus-slice LLM:
  G3 already achieved 6/6 Top-1 on this same two-case intersection.
- No claim of general repair effectiveness or statistical significance.
- No proof that a runtime-passing patch is the intended developer repair.
- Static semantic-delta validation covers only the two unique Top-1 candidates,
  not all 14 proposed alternatives or a larger benchmark.
